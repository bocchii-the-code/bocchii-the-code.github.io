Motivation & Objectives

Professional audio editing or mixing often requires experts to navigate complex GUI environments in the Digital Audio Workstations (DAWs). For music or audio editing, the threshold is reasonably high and the learning curve is painful. For light users who just want to apply a quick effect or convert formats, a natural language driven audio edting engine would be more beneficial than traditional DAW.

The Problem: Translating creative intent ("Make this sound like it's in a large hall and save it as an MP3") into technical operations (Pedalboard DSP + FFmpeg commands) is a bottleneck for non-technical users and a repetitive chore for experts.

The Solution: Mambo bridges this gap by using a Large Language Model (LLM) Agents as an orchestration layer to tranlate and execute audio processing tasks. It interprets natural language instructions and executes precise, deterministic tools to achieve the desired audio outcome.

Example Prompt
"Take the input file, apply medium distortion and a slight echo, then normalize the volume and convert it to a high quality mp3 audio file."
"Exract the first 10 seconds of the input file and apply a fade out effect."
"Make the first 5 seconds of the audio sounds loader."
"Shift the pitch of the input file 1 octave high and convert it to a WAV file."

ReAct System Architecture

Instruction Agent

The brain of the system that plans and orchestrates the workflow, powered by GPT-5.1 chat model. Uses pydantic dataclass to produce structured outputs with specific OutputFormat that specifies audio processing parameters, including DSP chains and ffmpeg shell commands.

Deterministic Tools

Direct integration with Pedalboard by Spotify for high-quality DSP and possible external plugin support and ffmpeg for robust audio file processing and transformations with runtime flexible toolcalls based on user specifications.

Self-Evaluation

A separate agent based on GPT-5.1 response model that validates planned actions before execution, ensuring higher reliability and "reasoning before acting."

Implementation Details

  • 01. Pipeline Orchestration: The pipeline manages runtime context, injecting available DSP effects into the LLM system prompt dynamically during runtime, allowing for flexible and modular agent behavior.
  • 02. Safty Check: Uses hard-coded command line check to avoid malicious actions and implements AST literal parsing in to convert LLM strings into Pedalboard instances safely, avoiding rejecting unkown codes via eval().
  • 03. Mode Flexibility: Supports Q&A Mode for brainstorming or general Q&A sections and Editor Mode for actual file processing via CLI.
  • 04. Vast Possibilities: Pedalboards supports external VST pluggins and instruments and allows more advanced editions to audio processing workflows (tentative).

Get Started

uv sync

python pipeline.py --file "INPUT_FILE_NAME.mp3"
